# 经验教训（Lessons Learned）

> 沉淀自：第4学期细化 + 通用智能排课器（scheduler.py）重写（2026-08-06）
> 原则：每条 = 现象 → 根因 → 修正 → 防再犯规则

---

## 一、架构层

### L1. "班级共享课表 + 渲染偏移(offset)" 模型脆弱
- **现象**：db 层 0 冲突，渲染层却 20 处双课（马原+电磁场、C+++电路实验等），且 `check_render` 不在 rebuild 流水线里，回归溜进"基线"。
- **根因**：db 共享行按电气班时间排，自动化/测控班靠 offset 平移"造"课表，平移结果从未校验；偏移后撞固定课。
- **修正**：重写为 **per-girl 直接排课**（CSP），每门课只受自身约束，彻底抛弃 offset。
- **规则**：渲染层 ≠ db 层，凡有"显示时变换"（偏移/映射）的校验必须查渲染后结果；`rebuild.sh` 必须包含渲染层校验。

### L2. 共享行模型有表达力上限
- **现象**：电磁场 4 人只能同时上课（每人基础候选都只有 offset 0），O302 同带 2 人被迫"合班"。
- **根因**：共享行无法表达"每人独立时间"，当固定课占满几乎所有槽位时无解。
- **修正**：接受合班（同老师同时=合班大课，合理）+ 输出警告；若必须每人错时，需 db 加 per-girl 维度。
- **规则**：先评估模型表达力是否覆盖需求，再谈约束求解；无解时先问"模型对不对"，别急着调参数。

## 二、算法层

### L3. 环形距离 bug 导致"合法解被判无解"
- **现象**：88 万节点穷尽搜索仍无解；单测放松约束后秒解。
- **根因**：同课两行间隔检查用了 `min(d, 5-d)`（环形距离），把"周一→周五"（差4天，合法）误判为间隔 1 天。
- **修正**：改为直接距离 `abs(wd1-wd2)`。
- **规则**：间隔/差值判断先想清楚"周内直接距离"还是"环形距离"；写错会静默排除大量合法解。

### L4. 无 MRV 的回溯必然爆炸
- **现象**：固定顺序 DFS，200 万节点超时；MRV（每次选候选最少任务）后 5000-7000 节点秒解。
- **根因**：贪心顺序把课挤占关键槽位，深层回溯组合爆炸。
- **修正**：MRV + 候选排序启发式（分散天、时段偏好）。
- **规则**：任何 CSP 先上 MRV；节点计数不要被"候选扫描的 ok 调用"污染（否则上限形同虚设）。

### L5. 对称/结构约束大幅剪枝
- **现象**：4 人全量无解，单人（surrey/taiyuan）可解。
- **根因**：电气班（surrey/taiyuan）同班同老师，应同步，但被当作独立变量翻倍搜索。
- **修正**：sync 同步（taiyuan 跟随 surrey 放置）；公共课固定位置（减少 6 个自由变量）。
- **规则**：排课前先识别"同班同步/公共课共享"结构约束，它们既是语义要求也是剪枝利器。

### L6. 无解排查：二分 + 逐项放松
- **现象**：全量无解，不知道哪门课/哪个约束堵死。
- **根因**：直接看全量搜索。
- **修正**：先放松"相邻同楼"→ 秒解，定位瓶颈；再逐门累积课程找罪魁（体育 slot5-6 被当 2 小节）；再逐个放松约束对比节点数。
- **规则**：无解三步走——① 放松单个约束看是否可解（判断瓶颈）② 逐门加课找罪魁（判断数据）③ 检查约束实现（判断 bug）。

## 三、领域口径层

### L7. 学时换算：下午 1 小节 = 2 学时
- **现象**：下午课被排成占"第三节+第四节"两小节（一天出现两次同一门课，按 4 学时误算）。
- **根因**：把"一次课=2小节"套用到下午（90分钟/节），忽略下午单节即 2 学时。
- **修正**：`slots_of` 按时段换算——上午/晚间 2 小节=2学时、**下午 1 小节=2学时**、四史 3 小节=3学时、实验 4 小节=4学时。
- **规则**：学时换算必须先定"每小节分钟数"：上午/晚间 45min=1学时、下午 90min=2学时。

### L8. 时段编号与起始时间
- **现象**：slot3 误为 09:50（应为 10:00 起）；末位编号 12（应为 10，连续编号）。
- **根因**：历史遗留（09:50 复制错、slot12 是旧架构"第12节"命名）。
- **修正**：全项目统一 slot1-10；slot3=10:00-10:45。
- **规则**：时段定义只在一处维护（db_schema.schedule 种子），其余全部引用；改时段要全局 grep 同步。

### L9. 同槽位复用 = 周次交集判定
- **现象**：一度以为"同格两课必须同楼"。
- **根因**：混淆"同槽复用"（周次错开、永不同时）与"相邻课"（时间连续、须同楼）。
- **修正**：冲突/教室/老师全部按 `weeks 交集` 判定；同槽复用的两课**不是相邻课**，无楼约束；只有 slot±1 且间隔≤30min 才查楼。
- **规则**：占用判定一律交集；"相邻"只对时间连续的不同课次生效。

### L10. 内容质量规则（用户明确）
- 实验课**禁止绪论**（8 节全为实操实验）
- 一天不能出现两个一样的课/两个实验（实验 4 学时=晚间 4 小节连续一次）
- 体育若在下午第一节，第二节必须留空（block_after）
- 优先 slot3（早上10点起）/ slot6（下午4点起），排不下才用其他
- 研楼三门=只能且必须在研楼；马原/习概=综合楼中教室（不可挪）

## 四、工程流程层

### L11. 校验覆盖不全导致既有问题漏网
- `check_render` 不在 rebuild.sh → 渲染冲突进基线；`check_locations` 只查 S1-2 → S3 电路(研楼)→概率论(综合楼) 8 处相邻冲突从未被发现。
- **规则**：新增校验必须进 rebuild.sh；校验范围（SEM_LIST 等）扩学期时同步扩。

### L12. 生成器与数据源耦合
- `gen_syllabus_sem4.py` 读共享表，架构改 per-girl 后读不到数据（0 门课）。
- **规则**：生成器从"权威数据源"读（per-girl 表），占位符↔渲染名要归一化映射。

### L13. 副产物完整性（sync/terms/主块）
- sync 同步只写 grid 不写 solution → 太原课表缺模电/数电/实验；
- rebuild 跳过 S4 后 terms 表缺行 → `semester_of` 全判 weekend；
- 主块写在函数定义前 → NameError。
- **规则**：任何"同步/派生数据"都要在导出侧补全；写库要补全依赖表（terms）；Python 主块放文件末尾。

### L14. 重构连锁 bug
- slot12→10 后 `course_scheduler.used_weeks` 仍排除 10/11 → KeyError。
- **规则**：改编号/命名后，全局搜索"排除/特判"旧值的地方（`if s != 10` 类）。

### L15. 展示与数据分离
- 汇报课表时把下午两小节合并成"14:30-17:40"一行，误导"下午少一节"。
- **规则**：汇报忠实于生成文件；合并展示要显式标注。

---

### L16. 固定块位置 = 容量平衡问题（不是"数据正确"就完事）
- **现象**：S5 实训按 courses_sem5.json 的 desc 排 1-4 半天/5-10 全天 → CSP 2M 节点超时；改 6-11/12-16（旧引擎同款）→ 34K 节点秒解。
- **根因**：实训周五全天 W5-10 堵死周五时，7 门理论（13节/周）+2 实验的周容量恰好打满 22 槽，深度回溯爆炸；12 周后电机学/电力系统基础结课，理论降至 9 节/周，容量充裕。
- **修正**：实训全天周放在半学期课结课之后（6-11 半天/12-16 全天，与 `总调度规则`"6+5"口径一致）；courses_sem5.json 的 1-4/5-10 desc 是未实现的数据漂移，已修正。
- **规则**：块状课程（实训/军训/综合设计）的周次选择 = 周容量规划问题，先用"每周课次×课时 vs 可用槽位"手算，再求解；数据文件的 desc 不等于已实施，以 db/进展记录为准，发现矛盾先诊断容量。

### L17. 同班模式（public）比 sync 更干净
- **现象**：S5 起初按 S4 模式用 sync（电气2人同步 + 自动化/测控分班），用户明确"第5学期起全部同班同专业（电气）"（后更正为**短2学期起**）后，改为全 public。
- **根因**：sync 只处理"电气班同步"，无法表达"4 人同一班"。
- **修正**：S5 全部课程 public=True（同时间/同老师/同教室，teacher_occ 防跨班同时），求解从 34K 节点降到 3941，渲染/导出天然按人展开。
- **规则**：同班 = public（语义与实现都最简）；sync 只用于"同专业部分同步"场景；改专业模式先问用户"从哪学期开始、覆盖哪些课"。

### L18. 字符串替换必须断言，否则静默失败
- **现象**：改 render_major.py 跳过 S5 时 `src.replace(old, new)` 未命中（原文是 `range(1,7)` 我写成 `range(1,6+1)`），脚本无断言照常打印"成功"，导致 rebuild ④ 用空表覆盖了 scheduler 的 S5 课表。
- **根因**：replace 失败返回原字符串，无任何报错。
- **修正**：所有对既有代码的字符串替换加 `assert src.count(old) == 1`；rebuild 后抽查关键产物（wc -l girl_schedules/*_sem5.md 非空）。
- **规则**：改文件后 grep 关键符号 + 抽查产物完整性，不能只看脚本"打印成功"。

## 五、总结检查清单（每学期细化前过一遍）

- [ ] 排课模型是否表达需求（per-girl vs 共享行）？
- [ ] 校验脚本是否覆盖本学期的全部层（db/渲染/地点/授课方案/虚拟时间）？
- [ ] 学时口径：下午 1 小节=2学时；实验晚间 4 小节？
- [ ] 时段编号/时间全局一致（slot1-10，slot3=10:00）？
- [ ] 同班同步/公共课共享已建模（sync/固定）？
- [ ] 间隔/占用判定用直接距离 + weeks 交集？
- [ ] 生成器读权威数据源，占位符↔渲染名归一？
- [ ] 写库补全依赖表（terms/girl_course_schedule）？
- [ ] 无解排查顺序：放松约束→逐门加课→检查实现 bug？
